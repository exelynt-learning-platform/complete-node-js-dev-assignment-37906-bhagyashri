Module: Week 1 Final Test

Assignment Title:
Version Control Project using Git & GitHub

Project Objective

Create a complete project and manage it using Git and GitHub. The project should demonstrate the complete version control workflow learned during Week 1, including repository creation, file tracking, commits, branching, merging, remote repository management, and GitHub collaboration practices.

1. Create the Project

Create a new project folder with a meaningful project name.

Example:

git-week1-project

Inside the project, create a simple application or project containing multiple files.

Example structure:

git-week1-project/
│
├── src/
│   ├── index.html
│   ├── style.css
│   └── script.js
│
├── README.md
├── .gitignore
└── notes.txt

The folder structure should be clear and organized.

2. Initialize the Git Repository

Open the terminal inside the project folder and initialize Git:

git init

Verify the repository:

git status

3. Create the Initial Commit

Add the required project files:

git add .

Create the first commit with a meaningful message:

git commit -m "Initialize project structure"

Commit messages should clearly describe the changes included in each commit.

4. Make Multiple Commits

Students must make multiple meaningful commits while developing the project.

Example:

git add .
git commit -m "Add project layout"

git add .
git commit -m "Add homepage styling"

git add .
git commit -m "Add basic project functionality"

Students should avoid meaningless commit messages such as:

git commit -m "changes"
git commit -m "update"
git commit -m "done"

5. Create and Use a Git Branch

Create a feature branch:

git switch -c feature-update

Make a meaningful change to the project.

For example:

- Add a new section.
- Improve the interface.
- Add a new feature.
- Update project documentation.

Stage and commit the changes:

git add .
git commit -m "Add project feature"

6. Merge the Feature Branch

Switch back to the main branch:

git switch main

Merge the feature branch:

git merge feature-update

Verify the merge:

git status

View the commit history:

git log --oneline

The feature branch changes should now be available in the main branch.

7. Handle a Merge Conflict

Students should understand how merge conflicts occur.

A merge conflict can happen when two branches modify the same part of the same file differently.

If a conflict occurs, Git will mark the conflicting section.

Students should:

1. Open the conflicted file.
2. Identify the conflicting changes.
3. Decide which content should remain.
4. Remove the conflict markers.
5. Save the file.
6. Stage the resolved file.

Example:

git add <file-name>

Complete the merge:

git commit -m "Resolve merge conflict"

If no conflict occurs naturally, students should explain the conflict resolution process in their project documentation.

8. Create a GitHub Repository

Create a new repository on GitHub for the project.

The GitHub repository should be public so that the instructor can access and review it.

Do not upload unnecessary or sensitive files.

9. Connect the Local Repository to GitHub

Add the GitHub repository as the remote:

git remote add origin <repository-url>

Verify the connection:

git remote -v

Rename the branch to main if required:

git branch -M main

10. Push the Project to GitHub

Push the project to the remote repository:

git push -u origin main

After pushing, open the GitHub repository and verify that the project files and commit history are available.

11. Create README.md

The README.md file should provide a clear overview of the project.

It should include:

- Project name
- Project description
- Main features
- Technologies used
- Installation or setup steps
- How to run the project
- Basic usage information

Example:

# Git Week 1 Project

## Description

This project demonstrates the Git and GitHub version control workflow learned during Week 1.

## Features

- Organized project structure
- Git version control
- Feature branch development
- GitHub remote repository
- Project documentation

## Setup

Clone the repository:

git clone <repository-url>

Navigate to the project:

cd git-week1-project

## Usage

Follow the project instructions to run the application.

12. Create .gitignore

Create a .gitignore file and add files or folders that should not be tracked.

For example:

node_modules/
.env
.DS_Store
dist/

The .gitignore file should prevent unnecessary or sensitive files from being uploaded to GitHub.

13. Review the Repository

Before final submission, check the repository using:

git status

Check commit history:

git log --oneline

Check branches:

git branch

Check the remote repository:

git remote -v

Students should make sure that the working tree is clean and the latest changes have been pushed to GitHub.

14. Final Git Workflow

The complete workflow demonstrated in this assignment should be:

Create Project
      ↓
git init
      ↓
Create Files
      ↓
git add
      ↓
git commit
      ↓
Create Feature Branch
      ↓
Make Changes
      ↓
git add
      ↓
git commit
      ↓
Switch to main
      ↓
Merge Feature Branch
      ↓
Resolve Conflicts if Required
      ↓
Create GitHub Repository
      ↓
Connect Remote
      ↓
git push
      ↓
Verify GitHub Repository

15. Final Submission

Students should submit the GitHub repository link along with the required screenshots or command outputs requested by the instructor.

The GitHub repository should contain:

- Complete project files
- README.md
- .gitignore
- Multiple meaningful commits
- Main branch
- Evidence of feature branch development
- Merged changes
- No unnecessary files
- No passwords, API keys, tokens, or other sensitive information
